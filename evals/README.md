# evals —— 记忆系统的判断力测试

## 这些和单测有什么不同

单测问的是「**这个函数按我写的那样跑了吗**」。
evals 问的是「**跑出来的结果对吗**」。

半年里最贵的几次事故，单测全是绿的：

| 事故 | 单测为什么没抓到 |
|---|---|
| 新形状的卡算不出摘要，被整批丢弃（用户问「我有一只狗吗」，答记忆里没有） | 丢弃发生在**宿主的入口过滤**里，每个函数都按写的那样跑了 |
| 中文用户的花园两天翻成英文 | 判据函数**就是**按写的那样跑的，写错的是判据本身 |
| 落库闸吃掉真记忆 | 闸门函数返回了它该返回的值，错的是「该返回什么」 |

共同点：**代码没坏，判断坏了。** 判断力要用语料测，不能用断言测。

## 五层

```
不花钱，CI 每次都跑
  ① recall.py            挑卡 —— 卡在库里，问到了能不能召回来
  ② gate.py              落库闸 —— 该拦的拦住，**该放的放过**
  ③ garden_language.py   语言 —— 这个花园该用哪种语言
  ④ run.py 内的语料自查   语料本身没被删空/写坏

花钱，发布前跑
  ⑤ capture.py           落卡 —— 真模型写出来的卡对不对
```

```bash
python evals/run.py                 # 前四层
python evals/run.py --with-model    # 全部，发布前必跑
```

**④ 不是凑数的。** 语料被清空时，①②③ 会打印「0/0 通过」、退出码 0 ——
看起来比任何时候都健康。④ 是唯一能发现这件事的一层。

## 两个方向的失败，代价不一样

② 的语料里「该放过」的条目和「该拦住」的一样多，这是刻意的：

```
拦松了   垃圾卡进库 —— 用户在列表里看到「[摘要]」「...」，会来报 bug
拦紧了   真记忆被吃掉 —— 静默，不报错,用户只觉得「AI 记性不好」，永远不会报
```

所以 ② 会把「误杀真卡」单独标红。同理，① 对召回率下降容忍两个百分点的抖动，
但**违反禁忌一次都不容忍**。

## 宿主要多跑一层

③ 测的是**算法**（给定这些桶，结论该是什么）。
**证据从哪来**是宿主的事 —— 身份卡、历史消息、客户端 locale，内核碰不到。

宿主把自己的取证逻辑接上同一份语料跑：

```python
from evals.garden_language import run
run(decider=my_decider)   # decider(buckets, fallbacks) -> {"locale", "basis"}
```

这样内核和宿主守的是**同一条线**，不会各自跑偏。

## 改语料的纪律

**eval 抓不到它该抓的 bug 时，问题在 eval，不在被测代码。**

这条听起来是废话，但它每次都表现成同一个诱惑：一条 eval 红了，改语料让它变绿
最快。所以：

1. **每条断言必须写 `why`** —— 为什么这条该是这个结果。④ 会强制检查。
   没有 `why`，后来的人看到红条只能猜是代码改坏了还是语料写错了。
2. **事故进语料时写 `incident`** —— 标明这条是拿真事故换来的。它再红一次时，
   跑出来的报告会单独喊「**曾经真的发生过的事故，回归了**」。
3. **加了新判断，先做破坏性验证**：把错的实现插回去，确认 eval 真的会红。
   没红就是这层有洞 —— 现在补，比等它在线上表现出来便宜得多。
4. **改期望值要先说服自己**：是产品定义变了（可以改），还是实现退步了（不能改）。

## 语料里有什么

```
corpus/cards.jsonl          17 张卡：中英混、含敏感卡、含转折点、含噪声
corpus/queries.jsonl        10 条查询，带 must / must_not / why / incident
corpus/gardens.jsonl        15 个花园的桶构成，含 2026-08-24 事故当天的真实构成
corpus/gate.jsonl           该拦 / 该放的硬字段用例
corpus/gate_leak.jsonl      协议残片泄漏，含「一个弱证据不该打回」这条反向用例
corpus/conversations.jsonl   5 段对话窗口，给 ⑤ 用
```

**语料是编的，不是真实用户数据。** 内容全部虚构，不含任何真实用户的话、id
或可识别信息 —— 这个仓库是公开的。
