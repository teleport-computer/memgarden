# 记忆系统的 evals

## 这套东西回答一个单测回答不了的问题

单测证明**函数按写的那样跑**；eval 证明**跑出来的结果是对的**。

半年里最贵的几次事故全属于后者 —— 管道全通、单测全绿，而：

| 事故 | 症状 | 单测为什么没抓到 |
|---|---|---|
| 卡片形状不匹配 | 用户问「我有一只狗吗」答记忆里没有，**卡就在库里** | 挑卡函数本身没错，错的是喂进去的卡算不出摘要 |
| 老卡标题退出匹配 | 拿标题里的词召不回那张卡 | 翻译层"成功"翻译了，只是少带了一个字段 |
| 敏感闸空转 | 标记敏感的记忆在闲聊里照样被喂给模型 | 闸在跑，只是每张卡都被硬写成不敏感 |
| 中文花园翻英文 | 用户的记忆两天内整个换了语言 | 单测只覆盖「全中文」「全英文」两个干净极端 |
| 桶名混语言 | 约 1/3 的中文记忆被贴英文桶 | 提示词行为，而单测把 agent stub 掉了 |

**共同点：不是接线错误，是输出质量。** 这套 eval 就是给输出质量装上数字。

---

## 三层，各守各的

### ① 挑卡质量 `evals/recall.py` — 确定性、毫秒级、进 CI

标注好的语料（17 张卡 / 10 条查询）跑一遍挑卡策略，量四个数：

```
recall                must 里的卡召回了多少        ← 判罚
相关性段违反禁忌       把不该说的说出来了几次       ← 判罚，零容忍
零召回查询            该召回却一张都没有           ← 判罚
打底占用名额/查询      转折+最近两段的固定成本      ← 只观测
```

**判罚项与观测项分开是这条 eval 的核心。** 第一版把所有召回一视同仁，结果 8 条
查询全部"违反禁忌"，元凶却是同一张最新的噪声卡 —— 那是「最近 2 张」那一段的
**设计行为**（不看查询、永远塞最新的）。把设计当故障，eval 就废了。

阈值不对称：召回退步容忍 2 个百分点抖动，**违反禁忌一次都不容忍**。
漏召回是"没帮上忙"，把不该说的说出来是另一回事。

### ② 花园语言判定 `evals/language.py`（在 io 仓库）— 确定性

9 个场景，其中 `g03`/`g04` 是 2026-08-24 那次事故的现场形状。

这条住在 io 而不是包里：判定要读身份卡、历史记忆、客户端 locale，那些是宿主的
数据，内核碰不到。

### ③ 落卡质量 `evals/capture.py` — **调真模型、花钱、慢**

5 个对话场景，量五件事：产出语言是否跟花园语言一致、桶名是否落在该语言那一套、
有没有「健康/Health」这类双语斜杠串、落卡张数是否在期望区间、字段里有没有占位符。

**提示词行为的 bug 只有这一层能抓** —— capture/migrate 的单测都 stub 掉了 agent。

## 跑法

```bash
python evals/run.py                 # 只跑不花钱的
python evals/run.py --with-model    # 加真模型那层 —— 发布前必跑
python evals/recall.py --baseline evals/baseline.json   # 退步就非零退出
```

## 语料怎么维护

**每加一条语料，写清它对应哪个真实失败模式。** 没有失败模式支撑的语料只是凑数：
它永远绿，给人"已经测过"的错觉，而真正的漏洞在别处。

`queries.jsonl` 里的 `incident` 字段就是干这个的 —— 目前 10 条里 3 条直接
对应线上事故。

### 验证一条 eval 真的有效

**把它该抓的 bug 还原回去，看它红不红。** 没做过这个实验的 eval 不算数。

已验证过的：

```
把翻译层的 text_fields 改坏（还原"老卡标题退出匹配"）  → recall 红 ✅
关掉 any_score（还原"弱相关卡被滤掉"）                → recall 红 ✅
判定改回按字符数（还原"中文花园翻英文"）               → language 红 ✅
```

⚠️ 第一次做实验 1 时 **eval 没抓到** —— 因为它没模拟宿主的"入口过滤"（算不出
摘要的卡会被整批丢弃）。补上那一段之后才复现。**eval 抓不到它该抓的 bug 时，
问题在 eval，不在被测代码。**
